## 1. 输入契约

**核心规则：每一项缺失都有确定的降级行为——不报错，也不猜。**

| 输入项 | 必需性 | 缺失时的行为 |
| --- | --- | --- |
| 财务报表 Excel（资产负债表 + 利润表） | **必需** | 停止，向用户索取 |
| 数据截止日 asOf | **必需** | 提问获取（不从文件名推断） |
| 单位（元 / 万元） | **必需** | 脚本自动判定；判不出则提问 |
| 结算状态（草稿 / 已确认 / 已锁定） | **必需** | 提问获取，并印在报告上 |
| 现金流量表 | 可选 | 跳过现金流相关指标，脚注说明 |
| 同比基准（上年同期 / 期初数） | 基准 | 同比列标「无基准」 |
| 预算表 | 基准 | 预算列标「无基准」 |
| 同业基准 | 基准 | **恒为「无基准」**，见下 |
| 事业部收入归集表 | 下钻 | 不出收入明细章节 |
| 料工费成本构成表 | 下钻 | 不出成本明细章节 |
| 期间费用明细表 | 下钻 | 不出费用明细章节 |
| 含客户实名的 sheet | **排除** | 发现即跳过，并告知用户 |

### 关于同业基准

中国中小企业没有可靠的公开同业基准数据源。让模型联网搜出的行业均值是幻觉重灾区，且用户无法核对。

**决定：保持「MVP 不做」。** 若将来要做，唯一可靠形态是用户自行维护一份同业参考值表作为输入上传，而非由 agent 检索。

## 2. 领域函数

### 已有（直接复用）

| 能力 | 函数 |
| --- | --- |
| 盈利 | 毛利率、净利率、ROE、杜邦分解 |
| 营运 | 应收周转、存货周转、总资产周转 |
| 偿债 | 资产负债率、流动比率、权益乘数 |
| 发展 | 同比 / 环比 |

**三基准不是三套函数**，是同一指标的三列：本期 / 同比 / 预算偏差 /（同业）。

### 待新增（用户笔记中的下钻要求）

- 收入按事业部维度分解 + 各维度占比 + 各维度同比
- 成本按料工费分解 + 占比
- 期间费用三大类分解 → 每类下明细分解 + 占比 + 同比
- 税负分析 — **口径待定**：税负率？实缴对比预算？需先定义

### 三条不可动摇的规则

1. 所有除法走带护栏的比率函数；分母 ≤ 0 → 返回「不可算(原因)」。**不是 0，不是 N/A，不是空。**
2. 平均值缺期初数 → 用期末数近似，**并强制写脚注**。
3. **「不可算」是合法结论，不是失败。** 这条最容易在后期被当作「体验问题」优化掉，特此写死。

## 3. 输出模板

### 两段式

**第一段 — 对话稿（不是文件）**

```
① 四能力 × 三基准表
② 关键变化 3–5 条（只讲数据，不拍决策）
③ 疑问清单            ← 最重要的一段
④ 不可算项清单 + 原因
```

**第二段 — 用户确认后生成文件**

### Excel 模板（结构固定，模型只填数据）

| Sheet | 内容 |
| --- | --- |
| 指标总表 | 指标 / 本期 / 同比 / 预算偏差 / **计算口径** / **来源坐标** |
| 三表摘要 | 取数值 + 每个值指回 `sheet名!单元格` |
| 下钻 | 收入·成本·费用明细（有数据才生成） |
| 脚注与不可算 | 假设、近似、跳过项、疑问项 |

### Word 模板（章节固定，模型只填内容）

```
一、报告基本信息（asOf / 单位 / 结算状态 / 数据来源）
二、四能力分析（每能力：数据表 + 定性说明）
三、重点变化
四、不可算项与假设说明
五、数据信任链脚注
```

### ⚠️ T3 唯一的真断点

SKILL.md 第五步当前为「用 Skill 加载 xlsx/docx 技能，用 run_python 生成」——**这就是让模型自由写代码造文件**，违反不变量 1，也正是历史财务评测 5/7 超时的那条路径。

整个 skill 从头到尾都很克制，唯独最后一公里放开了自由度。

**修正方向：** Excel 中的占比、偏差用模板内预置公式；Word 用固定章节骨架；模型只提供填入的值。**结构固定，内容可变。**

这是 T3 需要新建的唯一一个东西。

## 4. 验收断言

**当前为零。** 这是最值钱的一件，分四层，各层归属不同的判定者。

### A2. 业务常识 — 代码断言，硬失败

**已实现**：`lib/domain/business-sense.ts` · `findImpossibleShares()`

- 占比类百分比不得 > 100%（容差 0.5 个百分点，吸收舍入）
- 只对**占比语义**生效；同比 / 环比 / 增长 / 完成率超 100% 合法，不得误报

来源与验证：HISTORY-005 曾以 `deterministicScore = 1.0` 全过，产出文档里却写着「Q4 营业利润占全年利润总额的 135%」「占 Q1 收入 116%」，当时只有 LLM judge 发现。该函数对 21 份真实评测产物回放：**精确命中 H005 两处，其余 20 份零误报**（含 `-141.7%`、`现金/营收 = 103.6%`、`同比 146.8%` 等合法超百分比）。

**接线状态：** 已接评测（`tests/history-eval/scoring.ts`，7 个 Case 全覆盖，critical）。**未接产品路径**——按 `CONTEXT.md`「校验类挂管道」的原则，正式挂点是渲染层；在渲染层建成前，产品侧不跑此断言。若 T3 需先于渲染层交付真实用户，必须先接临时挂点，否则产品中该断言等于不存在。

**待补（需结构化中间产物，文本层做不可靠）：** 单期数值不得超过同口径全期值、分期合计 = 全期合计。

### A. 取数正确 — 代码断言，硬失败

**A1 报表内部勾稽**

- 资产合计 = 负债合计 + 所有者权益合计（容差 ±0.01%）
- 流动资产 ≤ 资产合计；流动负债 ≤ 负债合计
- **单位一致性：所有数值在同一量级**（万元 / 元混用是真实世界最高频事故）
- 期间一致性：资产负债表期末日 = 利润表本期末；prior 期间对齐
- 每个 canonical 字段有来源坐标；无坐标 = 取数失败

**A2 业务常识勾稽**（来源：HISTORY-005 实际失败，见下）

- **任何"占比"不得 > 100%**
- **单期数值不得超过同口径全期值**（单季利润 > 全年利润 = 失败）
- **分期合计 = 全期合计**（容差内）；不等则必须显式说明差异来源

> **为什么必须补 A2：** 2026-08-04 评测中 HISTORY-005 的**确定性分是满分 1.0**，硬门全过，但产出物里写着「前 5 大客户占 Q1 收入 **116%**」和「Q4 单季营业利润占全年利润总额 **135%**」。
>
> **确定性断言查了单元格值和公式，没查数字合不合理。** 满分 ≠ 数字可信。A2 这三条是从真实失败里反推出来的，不是设想。

### B. 计算正确 — 代码断言，硬失败

- 每个比率的口径列非空，分子分母来自声明字段
- 分母 ≤ 0 的指标**必须**呈现为「不可算」；出现数字即失败
- 同比的分母是**上年同期**，不是上期
- 预算偏差的分母是**预算**，不是实际

### C. 结论一致 — semantic judge 唯一该管的事

**应当阻断：**

- 文字结论方向与数据一致（不得写「盈利能力改善」而净利率在降）
- **同一变动不得有两套互相矛盾的归因**（HISTORY-005 实例：研发费用同比 +62.5%，同时又归因为「研发支出结转管理费用」）
- **正文中的每个数字都能在指标表中找到**
- **不出现指标表中没有的新数字** ← 这一条一刀砍掉大部分幻觉
- 疑问项必须在文件中保留，不得被「合理假设」抹平

**不得阻断**（HISTORY-005 中 judge 实际越界的三类，需在 prompt 中显式禁止）：

- 某项变动**未加解释**（如「销售费用同比 -92.9% 未说明原因」）——属解释不足
- **四舍五入差异**——属精度，不属矛盾
- **judge 自己没拿到证据**（如「未独立读取单元格缓存值，无法验证数字真实性」）——属证据不足，是评测输入问题，不是交付物缺陷

### D. 交付完整 — completion gate

- 用户确认要文件后：1 个 xlsx + 1 个 docx，可打开
- **用户未确认时不生成文件，且不算失败**

> A/B 由代码断、C 由 judge 断、D 由 gate 断。
>
> 此前关于「评分器分层」的抽象争论，落到一个具体任务上就是这张表——**抽象时吵不清，具体了就没得吵。**
