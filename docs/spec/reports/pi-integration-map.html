三、八个切入点：做了什么，符不符合 pi 的规范

#切入点用到的 Pi APIFinwork 的做法规范判定
S1 Provider 注册
pi/provider.ts		 ModelRuntime.create({ credentials: InMemoryCredentialStore, modelsPath: null, allowModelNetwork: false }) + registerProvider() 单一 finwork-anthropic provider，baseUrl / apiKey 来自 AgentSettings；三处网络自发现全关 符合
但模型元数据是占位值 → 见 G2 / G3
S2 Session 创建 / 恢复
pi/agent-service.ts:120		 SessionManager.create(cwd, sessionRoot) / SessionManager.open(locator, sessionRoot, cwd) sessionRoot 强制 app-data/pi-sessions；恢复前用 validatePiSessionLocator() 做 realpath 越界校验 + .jsonl 后缀校验 符合且更严
缺保留期治理 → 见 G1
S3 资源加载器
pi/resource-loader.ts		 DefaultResourceLoader + systemPromptOverride / skillsOverride / additionalSkillPaths ambient 全关（noExtensions / noPromptTemplates / noThemes / noContextFiles），只装 Finwork 内置 + 用户 Skill 白名单，system prompt 走既有 SSOT 符合
override 钩子正是 pi 给宿主留的口
S4 工具适配
pi/tool-adapter.ts		 createAgentSession({ noTools: "builtin", customTools })；ToolDefinition{ name, label, description, parameters: TSchema, execute } 45 个中立 FinanceToolDefinition → session-scoped custom tools。Zod 仍是权威校验（parseAsync 在 handler 前跑），JSON Schema 只用于模型可见性；授权 / 审计 / 计时包在 execute 内 符合
"schema 给模型看、Zod 管执行" 是 pi 推荐形态，避免双份真相
S5 Skill 渐进披露
pi/skill-tool.ts		 自建名为 Skill 的 custom tool + 自建 <available_skills> listing pi 内置的 skill 注入依赖 builtin read，而 Finwork 把 builtin 全关了；因此自有化 listing 与受限 loader，避免为了 Skill 打开任意文件读取 有意偏离
理由充分且已记入 AR14 报告；实测使 AS0-08 输入 token −42%
S6 事件映射
pi/event-mapper.ts		 session.subscribe((e: AgentSessionEvent) => …) Pi 事件类型止于此文件；未知事件 drop 并留 trace。主链路过滤掉 run_started/ended/settled，交 Query 单一收口；子代理保留这三个并带 instanceId 符合铁律
S7 子代理
pi/subagent-runner.ts		 每个子代理一个独立 AgentSession + 独立 sessionRoot + subagent 模型槽 pi 无原生子代理概念；depth / 角色白名单 / dispatch 台账 / instanceId 全归 Finwork。未注入执行器时 fail-closed，不隐藏回落 符合
S8 打包发现性
pi/packaged-preflight.ts		 惰性 import() 所有 Pi 模块 + instrumentation.ts 环境变量守卫的 preflight Pi 是纯 ESM，顶层 import 经 tsx CJS 链会 ERR_PACKAGE_PATH_NOT_EXPORTED；显式 preflight 让 Next standalone trace 到 Pi 依赖 符合 Next 约束
S0 Pi Extension
未实现		 noExtensions: true 设计文档 §8 原本要求一个承载安全 hook / compaction 审计 / provider trace 的 Finwork extension；实现改成把授权内联进 tool-adapter 合理取舍，文档未同步
builtin 全关后确实不需要 tool_call 拦截，但 SSOT 没改 → 见 G7

六、迁移做得好的地方（值得保持的约束）

约束为什么重要目前靠什么守住
Pi 类型止于 lib/agent/pi/** 换 Provider 甚至换 runtime 都不用动 Query / SSE / UI / DB eval:ar13:pi-only 静态审计 + contracts.ts 的中立类型
Zod 是唯一权威校验 JSON Schema 转换若成第二真相，preprocess / refine 会静默失效 tool-adapter 在 handler 前 parseAsync；45 个工具共用一份 handler
session 只能落 Finwork 受控目录 防止 Pi 回落 ~/.pi，也防止恢复任意路径的 session validatePiSessionLocator() realpath 校验 + usesDefaultSessionDir() 断言
ambient 资源全关 用户机器上的 ~/.pi / ~/.claude 扩展不得渗进财务 session ResourceLoader 五个 no* 开关 + noTools: "builtin"
子代理执行器 fail-closed 不注入就报错，而不是悄悄回落到旧 runner —— 这条消除了 Pi-only closure 的隐藏引用 中立工具目录不再动态回落，主 Service 与子代理各自显式注入
run_settled 单一收口 终态语义只有一个所有者，子代理复用同合同但带 instanceId isQueryOwnedLifecycleEvent() 在 Service 侧过滤
