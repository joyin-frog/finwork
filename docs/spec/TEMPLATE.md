# 计划/Spec 输出规范（模板）

> 这是模板，不是 spec。Orchestrator 编写计划时复制本结构，产出 `docs/spec/spec-<任务名>.md`；
> implementer 完成后产出 `docs/spec/audit-<任务名>.md`（结构见文末附录）。
> 读者是**全新上下文的子代理**：它没有会话记忆、看不到对话历史，所以本文档必须自包含——
> 缺一条命令它就会盲跑，缺一个架构事实它就会重新发明。

- 明确排除的范围及理由。这是防范围蔓延的第一道闸，reviewer 会拿它对照 audit。

## 附录：audit 规范（implementer 产出 `docs/spec/audit-<任务名>.md`）

必须以 **Files changed 列表开头**（限定审查范围，必须完整），然后依次：

1. **Files changed**：创建/修改的每个文件
2. **每个文件改了什么**：一句话/文件
3. **与计划的偏差及原因**：无偏差也要写明"无偏差"
4. **测试结果**：实际执行的命令 + 输出结论（通过/失败原样报告）
5. **开放风险**：留给 reviewer 和 orchestrator 的注意事项
