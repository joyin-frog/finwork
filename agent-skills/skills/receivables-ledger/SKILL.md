# 应收账龄台账 Skill

**定位：两层并列只读查询与账龄呈现，催款草稿由人发送（红线：催款函不自动发送）。**

> **两层账龄口径声明（每次输出必须在末尾显式声明）：**
>
> | 层级 | 数据来源 | 账龄基准 | agingDays 符号 |
> |---|---|---|---|
> | 合同义务层 | fact_obligations（kind=receive） | 约定回款日（due_date） | 正值=未到期，负值=逾期 |
> | 销项发票层 | fact_invoices（direction=out） | 开票日（invoice_date） | 正值=已开票 N 天 |
>
> **两层符号方向相反，不得共用分箱逻辑或混合呈现。**

---

## 执行流程

---

### 合同义务层（第一～四步）

### 第一步：调用 query_receivables 获取应收清单

```
query_receivables(includeSettled=false)
```

若返回空清单（totalCount=0），说明当前无应收记录。**空清单不是错误**，引导语：
> "当前知识库中暂无应收记录。请先上传合同文件，并在知识库页面确认关键信息（对手方、金额、约定回款日）后，应收清单即可自动跟踪。"

### 第二步：账龄分箱呈现

账龄 = 约定回款日距查询日的天数（`agingDays`，工具已计算）。

**账龄分箱边界（集中在此处，唯一字面量来源）：**

| 分箱 | 条件 |
|---|---|
| 未到期（含今日到期） | agingDays ≥ 0 |
| 逾期 1-30 天 | -30 ≤ agingDays ≤ -1 |
| 逾期 31-60 天 | -60 ≤ agingDays ≤ -31 |
| 逾期 61-90 天 | -90 ≤ agingDays ≤ -61 |
| 逾期 90 天以上 | agingDays ≤ -91 |

**账龄口径声明（必须在报告末尾显式声明）：** 账龄自约定回款日起算（合同 due_date 字段），不从开票日计。

呈现用表格，示例格式：

```
## 应收账龄汇总（截至 YYYY-MM-DD）

| 分箱 | 笔数 | 金额合计（元） |
|---|---|---|
| 未到期 | N | X.XX |
| 逾期 1-30 天 | N | X.XX |
| 逾期 31-60 天 | N | X.XX |
| 逾期 61-90 天 | N | X.XX |
| 逾期 90 天以上 | N | X.XX |
| **合计** | **N** | **X.XX** |
```

**金额合计规则（严格执行）：**
- 金额来自工具返回的 `amountCents`（分值），换算：元 = amountCents / 100
- 禁止心算或从外部估算——一律用工具返回的分值换算
- 金额未知（amountCents 为 null）的笔数单列："另有 N 笔合同金额未知，未计入合计"
- 若所有行金额均未知，合计栏显示"无法汇总"

### 第三步：逾期催款清单草稿

对 agingDays < 0 的逾期项，生成催款清单草稿（措辞克制，不发送）：

```
## 逾期催款清单草稿

| 对手方 | 金额（元） | 逾期天数 | 合同来源 |
|---|---|---|---|
| XX公司 | X,XXX.XX | N 天 | 合同XX.pdf |
| ...（金额未知时标注"金额待确认"） |
```

**催款草稿措辞约束：** 只出清单，不起草催款函正文，不发送任何通知。

### 第四步：末尾三条固定声明

每次输出必须在末尾包含：

1. **账龄口径**：合同义务层账龄自约定回款日起算（正值=未到期）；销项发票层账龄自开票日起算（正值=已开票天数）——两层符号方向相反。
2. **金额未知说明**：（若有）另有 N 笔合同金额未知，已列出明细但未计入合计。
3. **回款核销说明（分场景）**：

   **在主对话中**：
   > 若您已收到某笔款项，请告知我（对手方名称与合同来源），我会起草"合同状态改为已收"草稿，**您在知识库页面点击确认后**，应收清单才会更新。

   **在子代理模式下（往来专员子代理）**：
   > 如需核销某笔应收（标记已收款），请回到主对话操作，在主对话中告知对手方名称与合同来源，主对话有权限完成核销确认。

---

## 输出段——逾期清单物化（WP14a）

第三步生成逾期催款清单草稿后，将逾期项物化为可勾选工件：

```
emit_checklist(
  title="逾期催款清单 [YYYY-MM-DD]",
  items=[
    { label="[对手方] · [金额/金额待确认] · 逾期 [N] 天", detail="合同来源：[filename]", severity="warn" }
    // 每笔逾期应收一条；severity 统一为 "warn"
    // 仅列逾期项（agingDays < 0）；未到期项不纳入
  ]
)
```

**正文 Markdown 表格保留**——工件是操作层（记录催款跟进进度），不替代正文阅读层。

### 销项发票层（第五～七步）

### 第五步：调用 query_sales_invoices 获取销项发票清单

```
query_sales_invoices(includeSettled=false)
```

若返回空清单（totalCount=0），说明当前无销项发票记录。**空清单不是错误**，引导语：
> "当前台账中暂无销项发票。如已开具发票，请调用 record_sales_invoices 登记。"

### 第六步：发票层账龄分箱呈现

账龄 = 查询日距开票日的天数（`agingDays`，正值=已开票 N 天，工具已计算）。

**⚠ 符号约定与合同层相反：合同层 agingDays 正值=未到期，发票层 agingDays 正值=已开票天数。两层不得混用分箱逻辑。**

**发票层账龄分箱边界（唯一字面量来源）：**

| 分箱 | 条件 |
|---|---|
| 已开票 0-30 天 | 0 ≤ agingDays ≤ 30 |
| 已开票 31-60 天 | 31 ≤ agingDays ≤ 60 |
| 已开票 61-90 天 | 61 ≤ agingDays ≤ 90 |
| 已开票 90 天以上 | agingDays > 90 |

invoice_date 为空的发票单列："另有 N 张开票日期未知，无法分箱"。

已回款（settlement_status='settled'）发票 agingDays=null，不参与分箱。

呈现用表格，示例格式：

```
## 销项发票账龄汇总（截至 YYYY-MM-DD）

| 分箱 | 笔数 | 金额合计（元） |
|---|---|---|
| 已开票 0-30 天 | N | X.XX |
| 已开票 31-60 天 | N | X.XX |
| 已开票 61-90 天 | N | X.XX |
| 已开票 90 天以上 | N | X.XX |
| **未回款合计** | **N** | **X.XX** |
```

### 第七步：高账龄销项催款清单草稿

对 agingDays > 30 的未回款销项发票，生成催款清单草稿：

```
## 销项高账龄催款清单草稿

| 客户 | 金额（元） | 已开票天数 | 发票号 |
|---|---|---|---|
| XX公司 | X,XXX.XX | N 天 | INV-XXX |
```

**收到回款时**：调用 record_invoice_settlement 登记实收金额与日期。
**催款草稿措辞约束**：只出清单，不起草催款函正文，不发送任何通知。

---

### 重复发票号跨方向说明（补充）

同一发票号在台账中是全局唯一主键（invoice_no PRIMARY KEY）。若系统报告"重复发票号"但实为同一客户不同批次的两张发票（业务上合理），需人工排查：
- 检查原发票号与新发票号是否确实相同（印刷误差、手录错误）
- 若确为不同发票，更正发票号后重新登记

---

## 执行约束

- **催款函禁止自动发送**：只出草稿，由人工决策后发送。
- **金额合计来自工具分值换算**：不心算，不从上下文估算。
- **空清单引导上传合同**：不报错，引导用户完善合同知识库。
- **账龄口径显式声明**：每次输出都在末尾声明口径（约定回款日）。
- **核销措辞分场景**：主对话可起草草稿待人确认；子代理无写权限，指示回主对话操作。
